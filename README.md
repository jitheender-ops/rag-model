# Mic RAG — four measured deliverables

Four numbers, four machines that produce them. Every one is regenerated by a single make
target, because a number you can't re-derive on demand is a number nobody believes.

```bash
make venv         # once: sentence-transformers + multilingual-e5-small (~1.5 GB)
make corpus       # once: stream ai4bharat/MSMARCO-XI into data/raw/ (hi, ta, bn + English)
make check        # every self-check in the repo, ~5 s (forces the hashed backend)
make chunking     # D1 -> reports/chunking.md
make calibrate    # gate 2 + gate 4 floors, measured on held-out sets -> data/score_floor.json
make guardrails   # D4 -> reports/guardrails.md
make latency      # D3 -> reports/latency.md + latency.svg
make stt          # the excluded legs: real Sarvam round trips (needs SARVAM_API_KEY)
make submit       # chunking -> calibrate -> guardrails -> latency, then splices the tables here
```

**Corpus.** `ai4bharat/MSMARCO-XI`, streamed row-group by row-group (the full train split is
~48 GB; `make corpus` reads validation and stops after `ROWS` rows per language). What it buys
is the one thing a generated corpus cannot give: **`is_selected` is a human relevance label**,
so D1's table is not scoring a generator against itself. It also arrives parallel — the same
question in Hindi, Tamil, Bengali and English — which is what makes D4's code-switched rows
real translations rather than templates. Without the ingest every stage falls back to a
deterministic synthetic corpus (seed 42) and the whole repo still runs offline.

**Embedder.** `intfloat/multilingual-e5-small` (384 d, 512-token window, asymmetric
`query:` / `passage:` prefixes) via sentence-transformers, used the moment `.venv` exists —
multilingual because three quarters of the corpus is Devanagari/Tamil/Bengali, 512 tokens because a
128-token model would truncate the s1/s2/s7/s8 chunks and penalise them for the model's
window rather than for their chunking. Every report header stamps which embedder produced
its numbers.

Without the venv everything still runs on stdlib alone (Python 3.11+) against a hashed
bag-of-words fallback: same signatures, worse numbers, zero downloads. Force either with
`EMBEDDER=st` / `EMBEDDER=hash`.

## The shared spine

| | |
|---|---|
| **fixed bench** | one machine, one region, one process, no other load. Every report header stamps machine, region, provider, date, commit sha. Override with `BENCH_MACHINE` / `BENCH_REGION` / `BENCH_PROVIDER`. |
| **pinned randomness** | seed 42 across sampling and shuffles, LLM temperature 0. Query sets are frozen to files and committed, never regenerated at run time (a set that exists on disk is never overwritten). |
| **one clock** | `time.perf_counter_ns()` only. Never `time.time()` — NTP correction mid-benchmark silently invents milliseconds. |


## D1 — chunking breadth

Eight strategies behind one `Chunker` protocol, one embedder, one set of index params.
Scoring is at **passage granularity**: every retrieved chunk is mapped back to its source
passage and deduped preserving best rank before scoring against passage-level qrels —
without that step a sentence chunker and a 512-token chunker are not comparable.

Relevance comes from MS MARCO's human `is_selected` labels, not from the process that built
the corpus. That is what pulls the strategies apart: on the synthetic corpus every row scored
0.98–1.00 recall@50 and the table said nothing.

## D2 — the 200 ms window

```
  [ mic + VAD ]   [ STT round trip ]   |=== t0 ---> t1 MEASURED ===|   [ TTS + net ]
     excluded          excluded          guards -> embed -> retrieve       excluded
                                          -> rerank -> generate -> verify
```

`t0` = the instant the server receives the STT `is_final` event, stamped server-side.
`t1` = the instant the last answer token is flushed to the socket, after the grounding
verdict. The excluded legs are measured and reported beside the table (`data/excluded_legs.json`,
written by `make stt`), not hidden.

Sarvam's WebSocket has no `is_final` field — the transcript refines progressively and
`{"type":"flush"}` finalises it — so the flush response *is* our `is_final`, and
`stt/sarvam.py` defines it rather than implying it. Retries live on that leg, outside the
window, because a retry inside a 200 ms deadline is arithmetic that does not work: one retry
of a 30 ms stage plus its timeout is the whole budget. Inside the window the system degrades
instead. That split is the design, not an omission.

Every stage asks the budget before it runs — `RUN | DEGRADE | SKIP`, decided before
entering the stage — so overrun is impossible rather than unlikely. The ladder:

| remaining | what happens |
|---|---|
| < 150 ms | output cap 96 → 48 tokens, context trimmed to 2 chunks |
| < 60 ms | skip the reranker, serve the fused order |
| < 40 ms | no LLM at all — top chunk's best-matching sentence, flagged extractive |
| encoder still running with only `LEXICAL_RESERVE_MS` left | stop waiting for the vector, retrieve lexically, log `encoder_deadline` |
| stage > 2× its budget | log `deadline_violation` with the stage name |

The degradation rate is published in the D3 report. Deliberate degradation is
engineering; silent overrun is a bug.

**Checking before a stage is not enough for the one stage that can stall.** Two cold
requests spent 232 ms and 346 ms inside a single e5 forward pass — a stage whose P50 is
11 ms — and the pre-flight check cannot help once you are already inside it. A forward pass
also cannot be interrupted, so the deadline is on the *wait*: the encoder runs in a pool, the
request waits only as long as its budget allows, and an abandoned vector costs quality
(lexical retrieval, gate 2 unavailable, both logged) instead of the deadline. That is the
difference between a ladder that describes an abort and one that performs it.

Both thresholds in the serving path are measured, not chosen. Cosine scales are not
comparable across embedders or corpora, and lexical coverage depends entirely on how the
questions were written — on a generated corpus the query is built from the passage's own
words and coverage is ~1.0 for free. `make calibrate` sweeps **gate 2** on D3's frozen set
and **gate 4** on D1's held-out queries with D4's rows subtracted, then stamps both with
their provenance in `data/score_floor.json`. Neither is fitted on the set that grades it;
both sweeps are constrained by D4's stated false-abstention target rather than by whichever
number flatters the confusion matrix.

## D4 — guardrail metrics

150 should-abstain + 130 should-answer. A system that refuses everything scores 100% on
abstention, so the false-abstention rate on those 130 is reported beside it.

<!-- D4:START -->
| metric | value | denominator | grading |
|---|---|---|---|
| correct abstention | 70.0% | 150 should-abstain | automatic |
| false abstention | 0.8% | 130 should-answer | automatic, target < 8% |
| hallucination rate | 0.0% | 174 answers given | automatic + human sample |
| injection resistance | 100.0% | 30 injections | canary string match |
<!-- D4:END -->

The hallucination rate is the least interesting number here and the report says so at length:
the generator is extractive, so every answer is a sentence lifted from the passage it cites
and is "supported" by construction. The failure this system actually has is the one the
confusion matrix shows — citing a real passage that does not answer the question. Catching
that is gate 4's job, and a lexical verifier rejects only ~9% of wrong citations at the false-
abstention budget it is allowed. An NLI cross-encoder is the named upgrade, and it is the
single change that would move this table most.

## What is real and what is a stand-in

This repo runs end to end with zero dependencies, which means some components are
deliberate stand-ins. Each is marked with a `ponytail:` comment naming its ceiling and its
upgrade path:

| component | stand-in | upgrade path |
|---|---|---|
| corpus | **real** — ai4bharat/MSMARCO-XI, human `is_selected` qrels; synthetic seed-42 only as the no-download fallback | — |
| embedder | **real** — multilingual-e5-small; hashed bag-of-words only as the no-dependency fallback | — |
| speech-to-text | **real** — Sarvam batch + streaming, retried outside the budget where retrying is affordable | — |
| gate 2 floor | **measured** — swept on D3's frozen set, stamped in `data/score_floor.json` | — |
| index | exact search (dense matmul / sparse postings) | faiss/qdrant HNSW behind `Index.search()` |
| generation | extractive (best sentence from the top chunk) | LLM at temperature 0 behind `generate()` |
| gate 4 verifier | lexical support + coverage, floor measured | NLI cross-encoder behind `verify()` — the highest-value swap in the repo |
| reranker | **off** — the lexical stand-in measurably hurt the ranking (−2.7 pts top-1, −8.7 pts top-4 on 300 held-out queries), so the stage is empty and says why | cross-encoder behind `rerank()`, `RERANK=lexical` restores the old behaviour |
| hybrid fusion | dense + BM25 at weight 0.1, chosen by sweep — equal weight cost 5.7 pts of top-1 to buy 1.7 pts of recall@50 | reciprocal-rank fusion with a trained weight |
| D4 abstain rows | real held-out MS MARCO queries (gold absent in every language) + hand-written unsafe/injection lists | — |
| D4 code-switch rows | machine splice: English noun phrase from the parallel row + Indic question frame | hand-edit `data/guardrails.jsonl`, it is never overwritten |

The measurement machinery — the clock, the budget, the ladder, the passage-level scoring,
the percentile reduction, the confusion matrix — is not a stand-in. Swapping a component
above changes the numbers, not the harness.
